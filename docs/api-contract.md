# Coyote Supply · контракт API v1

Frontend и backend используют один формат JSON. [Машиночитаемые схемы](api-schema.json) описаны в `$defs`. [Фикстуры](fixtures/) показывают ожидаемые тела запросов и ответов. Все даты и количества в них синтетические.

| Метод и путь | Запрос | Успешный ответ `200` | Пример |
|---|---|---|---|
| `GET /api/health` | — | `health`, тело `{"status":"ok"}` | — |
| `GET /api/stores` | — | `stores` | [Список точек](fixtures/stores.json) |
| `GET /api/stores/{id}/forecast` | — | `forecast` | [Шымкент](fixtures/shymkent-demo/forecast.json) · [Алматы](fixtures/almaty-demo/forecast.json) |
| `GET /api/stores/{id}/draft` | — | `draftResponse` | [Сохранённый](fixtures/shymkent-demo/draft-saved.json) · [Пустой](fixtures/almaty-demo/draft-empty.json) |
| `PUT /api/stores/{id}/draft` | `draftRequest` | `draftResponse` | [Запрос](fixtures/shymkent-demo/draft-request.json) · [Ответ](fixtures/shymkent-demo/draft-saved.json) |

`{id}` совпадает с `storeId`. Все имена полей JSON в camelCase. Значения количества целые в базовых единицах `ml`, `g`, `pcs`. Цены и итоги — целые тенге. Момент времени передаём с UTC-смещением, календарные дни — `YYYY-MM-DD` в зоне точки. Обязательное поле с `null` означает неизвестное или отсутствующее значение. `0` означает рассчитанный ноль. Пустой массив означает отсутствие элементов.

## Прогноз

`asOf` — момент, на который построен расчёт. `forecastId` непрозрачен для клиента. Для одних и тех же входных данных и настроек одной точки он стабилен. Меняется при изменении исходного снимка, настроек или версии модели. `dataMode` содержит `synthetic` для встроенного набора или `imported` для снимка из `COYOTE_DATASET_PATH`.

`schedule` описывает окно оформления и прихода. `orderDeadlineAt` — до какого момента можно оформить заказ, `arrivalDate` — первый достижимый приход, `nextArrivalDate` — следующий после него. `schedule: null` означает неизвестный календарь и отсутствие рекомендаций по объёму.

По каждой позиции:

- `onHandQty` — остаток на момент расчёта. `daily` упорядочен по возрастанию даты, от дня расчёта включительно до следующего после целевого прихода исключительно. Это базовый сценарий без предлагаемой закупки. `incomingQty` включает только подтверждённые приходы. `closingQty` — остаток на конец дня после расхода и исключения партий с истёкшим сроком. `unmetQty` — непокрытый спрос за день. `expiringQty: null` означает отсутствие расчёта по партиям.
- `recommendedQty` — объём после округления по `packQty`. При `dataStatus: needs_review` значение и `explanation` равны `null`. Если ежедневную симуляцию построить нельзя, `daily` пуст. Причина указана в `risks`. Отсутствие сроков партий само по себе не блокирует закупку, если суммарный остаток и остальные исходные данные известны.
- `explanation` содержит потребность и дефицит до прихода, непокрытую потребность окна после прихода, целевой резерв, остаток в конце окна без новой закупки и объём до округления. Формула последнего: `uncoveredWindowDemandQty + max(0, safetyStockQty - endStockWithoutOrderQty)`.
- `stockout` показывает первую дату нехватки до целевого прихода, объём в этот день (`firstUnmetQty`) и суммарный дефицит до прихода (`quantity`). `excess` — объём выше допустимого максимума на конец окна. `expiry` — объём риска по партии `lotId` на её дату годности. `insufficient_data` содержит код `reason`. Типы рисков могут сочетаться.

Контрольный пример: [молоко в Шымкенте](fixtures/shymkent-demo/forecast.json) имеет 20 000 мл в наличии, суммарный дефицит 17 000 мл и первую нехватку 5 000 мл 10 ноября. Рекомендация 24 000 мл относится к окну после прихода 12 ноября. Это две разные задачи для управляющего.

## Черновик

`GET` возвращает `{"storeId":"…","draft":null}`, пока черновик не сохранён. Сохранённый черновик содержит `forecastId`, строки с упаковками, зафиксированными ценами и суммами, итог и время записи `savedAt`. Если прогноз изменился, `GET` всё ещё возвращает сохранённый черновик с прежним ID. Клиент сравнивает его с текущим ID и предлагает перепроверить строки перед новым сохранением.

`PUT` заменяет весь черновик точки в одной транзакции. Перед записью проверяется актуальность `forecastId`, затем состав строк. Строки содержат только `ingredientId` и положительное количество, кратное размеру упаковки. Повтор позиции, чужой или неизвестный идентификатор, неизвестная рекомендация и недопустимое количество отклоняются. Позицию можно убрать из массива, а рассчитанный ноль не мешает добавить позицию вручную. Сервер берёт цену из каталога, умножает её на число упаковок и рассчитывает итог. При одновременном сохранении из двух вкладок выигрывает последняя успешная запись.

Явная очистка: `PUT` с актуальным `forecastId` и `rows: []` удаляет черновик точки и возвращает `draft: null`. Повторная очистка возвращает тот же результат. Редактирование черновика не изменяет склад, прогноз или внешние заказы.

| Статус | `error.code` | Действие клиента |
|---|---|---|
| `404` | `store_not_found` | Показать, что точка недоступна. |
| `409` | `stale_forecast` | Обновить прогноз, сохранить локальный ввод и дать сверить его заново. [Пример](fixtures/error-stale-forecast.json). |
| `422` | `invalid_draft` | Показать конкретную ошибку рядом с полем, сохранить введённые количества. |

Ошибки из таблицы имеют общий формат `error` из схемы. `message` предназначен для интерфейса. Каждый объект `details` указывает `path` и `reason`, например `rows.0.quantity` и `not_multiple_of_pack`. Сбой сети или неожиданный ответ сервера показываем как ошибку загрузки или сохранения с возможностью повторить.

## Подключение локального backend

- Запустите FastAPI по [инструкции для Windows](../README.md#backend-на-windows). Для Vite используйте базовый адрес `http://127.0.0.1:8000`. CORS разрешает `localhost` и `127.0.0.1` на портах Vite `5173` и `4173`. При раздаче сборки через FastAPI используйте относительные пути `/api/…`.
- Загрузите список точек, затем запрашивайте прогноз и черновик для выбранного `storeId`. Используйте последние ответы для этой точки. Сравнивайте `draft.forecastId` с текущим `forecastId` перед сохранением.
- Для сохранения передайте `Content-Type: application/json`, текущий `forecastId` и весь список выбранных строк. Количество 0 в редакторе означает исключение строки из массива. Рассчитанный ноль в прогнозе можно изменить вручную. Строку с `recommendedQty: null` сохранить нельзя.
- На карточке оценка стоимости рекомендации равна `recommendedQty / packQty * packPriceKzt`. После сохранения используйте серверные `lineTotalKzt` и `totalKzt`. Время сохранения возвращается в UTC.
- При `409` загрузите новый прогноз и сохраните ввод для сверки. При `422` сопоставьте `details[].path` с полями редактора. Для сетевого сбоя и ответа `5xx` оставьте возможность повторить.

[Примеры из работающего API](fixtures/live/) содержат полный прогноз обеих точек,
запрос ручной правки, ответ с сохранённой ценой и пустой черновик. Идентификатор
из файла служит примером. Для записи всегда берите `forecastId` из текущего ответа.

Формула прогноза расхода одинакова для всех позиций. Для каждой даты выбираются
до четырёх последних полных наблюдений с тем же днём недели до дня расчёта.
Медиана округляется вверх до целой базовой единицы. Подтверждённый ноль участвует
в расчёте. При менее чем трёх наблюдениях позиция требует проверки. Пропуск
актуальной техкарты для затронутой позиции также требует проверки. Для
скоропортящегося товара неизвестный срок годности отмечается
`unknown_lot_expiry`. Известные партии по-прежнему могут давать риск списания.
